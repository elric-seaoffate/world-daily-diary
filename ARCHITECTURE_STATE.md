# World Daily Diary - Locked Architectural Rules (Do Not Regress)
1. **Worker URL:** `https://world-daily-diary.nigel-ferguson10.workers.dev`
2. **70-Feed Hourly Scatter-Gather (7 Feeds/Worker + Hourly Consolidation):** `handleHourlyIngest` splits all 70 feeds into 10 shards of 7 feeds (`SHARD_SIZE = 7`). Shard 0 runs inline; Shards 1..9 are pushed to `NEWS_QUEUE` with staggered `delaySeconds: s * 6` so Cloudflare processes 1 shard per Worker invocation (7 subrequests per worker). When the final shard (`s9`, at +54s) finishes, `consolidateHourlyShards` merges and deduplicates `s0..s9` into the master hourly key `rss-hourly-YYYY-MM-DD-HH` and master health key `rss-health-YYYY-MM-DD`.
3. **10ms CPU Ceiling (`Error 1102`):** Never use O(N^2) nested loops or per-comparison regex/NFD normalization. Compute 5-char stems once on ingest (`_stems`), use an O(N) inverted index (`preClusterAndSortByTopic`) to group topic-linked stories together, and pass small groups of 18 headlines to `@cf/meta/llama-3.2-1b-instruct` in a 2-stage hierarchy.
4. **Strict Prose Formatting:** All BookStack output must be pure flowing paragraphs—no internal subheadings, bullet points, or numbered lists. Enforced via `CONFIG_KV` prompts + `cleanLlmProse()` regex post-processor.
5. **Post-Creation Dual-Archive Historical Context LLM:** After the primary LLM writes the story (`eventReport` + `analysisReport`), a dedicated archivist LLM pass queries BOTH `published_stories` (our previously generated diary entries) AND `articles` (90-day raw RSS historical feeds). If >=2 non-generic topic stems match, it synthesizes `### 90-Day Archive Context`. Raw `articles` older than 90 days are automatically pruned at publish time.
